# 任务计划 — 普通用户 WebUI 能力矩阵

## 执行约束

- **可改文件**：
  - `web/src/utils/capabilities.ts`（新建）及/或 `dashboard-sections.ts`、`edition.ts`
  - `web/src/utils/nav/*`（`index.ts`、`shared.ts`、`personal.ts`、`team.ts`、`visibility.ts`、必要时 `types.ts`）
  - `web/src/router/index.ts`
  - `web/src/composables/useNavigation.ts`、`useEdition.ts`（若需读 capabilities）
  - `web/src/views/Dashboard.vue`、`components/dashboard/*`（含 `HomePipelineCard`、`PersonalHomeHero` 等）
  - `web/src/views/pipeline/*`、`PipelineModes.vue`、`MinimalChat.vue`（复用，不新建平行聊天页）
  - `web/src/views/Memory.vue`（query/full 模式，同文件）
  - 相关 `web/src/**/*_test.ts` / `__tests__`（若项目已有 vitest 模式则跟随；否则以可运行的纯函数单测为准）
  - `docs/guide/multi-tenant.md`、必要时 `profile-getting-started.md`
  - `docs/versions/v0.2.6/普通用户WebUI能力矩阵/*`
  - **仅当核对后确有缺口**：`core/pkg/server` 下 storage 相关 handler 的角色校验（最小补丁，不新 API）

- **不可改文件 / 禁止事项**：
  - **禁止**新增 edition 专用业务 API（backends/pipelines 协议不变）
  - **禁止**新建 `*Personal.vue` / `*TeamUser.vue` / `ChatAdmin.vue` 等平行页面
  - **禁止**删除 `/api/v1/backends`、`/api/v1/pipelines` 注册或首页对其的调用
  - **禁止**本迭代合并 Host/System/Clash 为单文件（P3 可选，默认不做）
  - **禁止**扩大 minimal 路由白名单（除非单独立项）
  - **禁止**改 Team Admin「人+共享资源」主体信息架构（仅加测试对话 + 存储配置入口）
  - 不改 billing / migrations / auth 核心（除非 storage 403 最小补丁需要）

- **遵循规范**：`docs/harness/CONVENTIONS.md`、`ARCHITECTURE.md`、`ANTI-PATTERNS.md`、`web/AGENTS.md`；复用原则见技术方案 §0

## 开发风险与任务映射

| 风险 ID | 等级 | 归属任务 | 验收如何覆盖 |
|---------|------|----------|--------------|
| R01 | High | T4, T8 | 路由单测/断言：列表 redirect、`:id`/`create` 放行；浏览器 U15 |
| R02 | High | T3, T8 | admin `pipelineTestChat`；浏览器 U12（team_admin） |
| R03 | High | T1, T2, T8 | 无平行页面；capability 单测；CR/`rg`；浏览器 U19 |
| R04 | High | T6, T8 | storage 导航+守卫；写接口 403（若需）；浏览器 U07/U16 |
| R05 | High | T8 | 强制 Browser MCP 正本；P0 用例 pass；产出 JSON |
| R06 | Medium | T5 | 首页仍调统一 backends API；无「去完整后端页」误导 |
| R07 | Medium | T6 | personal=`full`；team_user=`query`；浏览器 U08 |
| R08 | Medium | 边界 | 代理三页合并 / Chat 大重构 **不进本迭代** |
| R09 | Low | T4 | minimal 仍 `MINIMAL_ALLOWED`；不扩大 |

> High 已全部映射；Critical 开放数 = 0。

## 建议执行顺序

```
T1  getCapabilities 真源 + 单测
      ↓
T2  导航按 capability 同源生成（去对话/去普通用户配置组）
      ↓
T3  全角色 pipelineTestChat（含 Team Admin）
      ↓
T4  路由意图：列表 redirect / 深链放行 /chat redirect / storage 拦 user
      ↓
T5  首页收敛：去「开始对话→/chat」；保留统一 API 面板
      ↓
T6  记忆 query 模式 + 存储配置导航/白名单（+ API 核对）
      ↓
T7  本机代理导航上提 + multi-tenant 文档同步
      ↓
T8  【强制】UI 浏览器验收 +（建议）HTTP admin-e2e
```

## 任务列表

### 任务 T1：`getCapabilities` 真源与单测

| 属性 | 值 |
|------|----|
| 功能点 | Capability 矩阵（方案 §3.2） |
| 前置依赖 | 无 |
| 难度 | M |
| 关联风险 | R03 |
| 验收标准 | 存在 `getCapabilities(edition, isAdmin)`（或等价）；对 personal / team_user / team_admin / minimal 断言关键位（如 `nav.chatPage===false`、`pipelineTestChat===true`、team_user `storageConfig===false`）；单测可运行通过；`dashboard-sections` 可由 capability 派生或明确委托，避免两套互相打架 |
| 风险缓解 | 能力差异集中一处，降低复制页面诱惑 |

**执行步骤**：

1. 新增 `web/src/utils/capabilities.ts`（或扩展 `dashboard-sections.ts` 并导出统一入口）
2. 实现矩阵与 TypeScript 类型
3. 编写单测覆盖四角色关键位
4. 确认不引入新 HTTP API

### 任务 T2：导航按 capability 同源生成

| 属性 | 值 |
|------|----|
| 功能点 | Personal / Team User 同源导航；Admin 独立运维导航 |
| 前置依赖 | T1 |
| 难度 | M |
| 关联风险 | R03 |
| 验收标准 | `getNavMenu` 消费 capabilities；Personal 与 Team User **同一生成路径**（仅 `myTenant` / `storageConfig` / `systemConfig` 等位不同）；侧栏无「对话」；普通用户无「配置→后端/策略」；Admin 仍有共用后端/策略；`rg "chatNav"` 不再出现在普通用户菜单组装中（或仅被 capability 关掉） |
| 风险缓解 | 消灭平行 `NAV_MENU_*` 业务漂移 |

**执行步骤**：

1. 重构 `nav/index.ts` + `shared.ts` / `personal.ts` / `team.ts`
2. 去掉普通用户 `personalConfigGroup` 侧栏入口、去掉 `chatNav` 一级
3. Team User：无 `storageConfig`；有 `myTenant`
4. 手动或单测：flatten 后菜单 id 集合符合矩阵

### 任务 T4：路由意图守卫（列表 / 深链 / chat / storage / minimal）

| 属性 | 值 |
|------|----|
| 功能点 | 入口策略（方案 §3.3.3）；不删 API |
| 前置依赖 | T1, T2 |
| 难度 | M |
| 关联风险 | R01, R04, R09 |
| 验收标准 | personal/team_user：`/backends`、`/pipelines`（列表）→ redirect dashboard；`/pipelines/create`、`/pipelines/:id` **放行**；`/chat` → redirect dashboard；team_user：`/storage`、`/data-stores`（及约定的 cache）→ dashboard；team_admin：上述列表页可进，且白名单含 storage（若 T6 已加）；minimal：仍仅 `MINIMAL_ALLOWED`；有可运行断言（router 单测或等价）覆盖深链 vs 列表 |
| 风险缓解 | 防止误伤编辑深链；拦住 user 存储直链 |

**执行步骤**：

1. 在 `edition.ts` / `router/index.ts` 实现基于 role+capability 的策略函数
2. **禁止** `path.startsWith('/pipelines')` 一律 redirect
3. 单测：至少覆盖 R01 矩阵（list deny / id allow）
4. 不删除 backends/pipelines handler
