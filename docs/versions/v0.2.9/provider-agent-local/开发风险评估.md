## 3. Critical / High 专项

### R01 — 账户池重试延迟与计费翻倍

- **触发条件**：upstream 429，账户池 3 Key，MaxRetries=3，每 Key 均 429。
- **最坏结果**：单用户请求 4 次 upstream（原 Key + 3 切换），延迟 4×，Token 若已产生则重复计量。
- **缓解措施（编码前可做）**：
  - 429 切换不计入 pipeline MaxRetries 的「业务重试」，单独 `account_failover_max=2` 配置；
  - 切换前未收到 response body 的不记 Token；
  - 在 `RecordFailure` 区分 `rate_limit` vs `hard_error`。
- **验证方式（可执行）**：
  ```bash
  go test ./core/pkg/backend/... -run TestAccountPool429Failover -count=1
  go test ./plugins/backend/openai/... -run TestAccountPool -count=1
  ```
  httptest mock：第 1/2 Key 返回 429，第 3 Key 返回 200；断言 upstream 调用次数 ≤ 3。
- **残余风险**：可接受（有上限）

### R02 — 流式/非流式账户选择不一致

- **触发条件**：`Dispatch` vs `DispatchStream` 各自实现选 Key。
- **最坏结果**：流式会话绑定 key-1，非流式用 key-2，配额与亲和失效。
- **缓解措施**：
  - 新建 `backend.AccountPoolSelector`，在 `BackendPlugin.Proxy` / `ProxyStream` 入口统一调用；
  - 选中的 accountID 写入 `context.Context`，熔断 Record 从 context 读取。
- **验证方式**：
  ```bash
  go test ./core/pkg/backend/... -run TestAccountPoolStreamParity -count=1
  go test ./core/internal/proxy/... -run TestStreamAccount -count=1
  ```
- **残余风险**：可接受

### R03 — 账户级与 backend 级熔断 key 冲突

- **触发条件**：同一 backend 同时 Record backendID 与 backendID::account::x。
- **最坏结果**：backend 被误熔断而可用账户仍健康，或反之。
- **缓解措施**：
  - 有 account_pool 时 **仅** Record 账户级；
  - `Allow()` 检查：任一健康账户则放行 backend；
  - `GetCircuitBreakerStatus` 聚合展示 backend 级汇总态。
- **验证方式**：
  ```bash
  go test ./core/pkg/scheduler/... -run TestAccountScopedBreaker -count=1
  rg 'RecordFailure|RecordSuccess' core/pkg/backend/ plugins/backend/
  ```
- **残余风险**：可接受

### R05 — Import/Export api_key 泄露

- **触发条件**：Export JSON 含明文 key；日志打印 backend 结构体。
- **最坏结果**：密钥进日志/截图/工单。
- **缓解措施**：
  - Export 增加 `?desensitize=true` 选项；
  - Backend/Account 的 `String()` 不输出 key；
  - Step 5 CR grep `api_key` 日志点。
- **验证方式**：
  ```bash
  rg 'api_key' core/pkg/logger/ core/pkg/server/backend_handler.go
  go test ./core/pkg/server/... -run TestExportDesensitize -count=1
  ```
- **残余风险**：可接受

### R09 — HotSwap 越权

- **触发条件**：Personal 用户 HotSwap 修改 tenant_id="" 的系统级 AgentProvider。
- **最坏结果**：多租户数据串扰。
- **缓解措施**：
  - HotSwap 仅允许改 `backend_id`/`model`；
  - 写操作校验：非 admin 只能改 tenant 自有或复制到 tenant 级配置；
  - 沿用 `resolveProviderReadTenantScope`。
- **验证方式**：
  ```bash
  go test ./core/internal/agent/... -run TestHotSwapTenantScope -count=1
  ```
- **残余风险**：可接受

### R11 — 无 account_pool 回归

- **触发条件**：Selector 未判 nil，空指针或误走 pool 分支。
- **最坏结果**：现有单 Key 后端全部 500。
- **缓解措施**：
  - `if cfg.AccountPool == nil || len(cfg.AccountPool.Accounts)==0`  early return；
  - 全量 `go test ./...` Gate 3。
- **验证方式**：
  ```bash
  go test ./core/pkg/backend/... -run TestNilAccountPoolCompat -count=1
  make test
  ```
- **残余风险**：可接受
