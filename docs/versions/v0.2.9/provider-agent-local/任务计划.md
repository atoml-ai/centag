## 任务列表

### 任务 1：账户池数据模型与 API

| 属性 | 值 |
|------|----|
| 功能点 | G1 账户池 |
| 前置依赖 | 无 |
| 难度 | M |
| 关联风险 | R01, R02, R12 |
| 验收标准 | `go test ./core/pkg/backend/... -run TestAccountPool -count=1` 全部通过 |
| 风险缓解 | 账户切换上限 = min(MaxRetries, len(accounts)-1)；429 才切换；metrics 计数 |

**执行步骤**：

1. 在 `core/pkg/backend/backend.go` 新增 `BackendAccount` 和 `AccountPoolConfig` 结构体
2. 扩展 `BackendConfig` 增加 `AccountPool *AccountPoolConfig` 字段
3. 新建 `core/pkg/backend/account_pool.go` 实现调度策略（round_robin、least_usage、sticky_session）
4. 实现 `AccountPoolSelector`，在 `BackendPlugin.Proxy` / `ProxyStream` 入口统一调用
5. 新增账户级熔断器 key：`{backendID}::account::{accountID}`
6. 实现账户 CRUD API：
   - `GET /api/v1/backends/:id/accounts`
   - `POST /api/v1/backends/:id/accounts`
   - `PUT /api/v1/backends/:id/accounts/:accountId`
   - `DELETE /api/v1/backends/:id/accounts/:accountId`
7. 编写单元测试验证账户池调度逻辑

### 任务 3：账户池调度策略实现

| 属性 | 值 |
|------|----|
| 功能点 | G1 账户池 |
| 前置依赖 | 任务 1 |
| 难度 | L |
| 关联风险 | R01, R02, R12 |
| 验收标准 | `go test ./core/pkg/backend/... -run TestAccountPoolStreamParity -count=1` 全部通过 |
| 风险缓解 | 账户选择提取为 `SelectAccountForRequest()` 单函数；流/非流共用 |

**执行步骤**：

1. 实现 `round_robin` 策略：健康账户间轮询
2. 实现 `least_usage` 策略：选窗口内请求量最低者
3. 实现 `sticky_session` 策略：按 `X-Session-ID` / OpenAI `user` / Anthropic `metadata.user_id` 绑定账户
4. 实现会话亲和 key 提取优先级：
   - Header `X-Session-ID`
   - OpenAI 请求体 `user` 字段
   - Anthropic 请求体 `metadata.user_id`
   - 无 key → 退化为 `least_usage`
5. 在 `plugins/backend/openai/` 和 `plugins/backend/anthropic/` 中集成账户池
6. 编写集成测试验证流式/非流式路径账户选择一致性
