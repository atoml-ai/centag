## 3. Critical / High 专项

### R01 — 价格表缓存与 DB 不一致

- **触发条件**：管理员通过 API 修改 pricing_rules，但缓存未失效
- **最坏结果**：用户请求使用旧价格计费，导致费用计算错误
- **缓解措施（编码前可做）**：
  1. 使用 TTL 缓存（默认 5 分钟）
  2. 提供 `InvalidateCache()` 方法，在规则变更时主动调用
  3. 缓存 key 包含规则版本号
- **验证方式（可执行）**：
  - 单测：`go test -run TestPricingCacheInvalidation ./internal/billing/...`
  - 手动：修改规则后立即查询，确认新价格生效
- **残余风险**：可接受（TTL 窗口内最多 5 分钟偏差）

### R05 — 硬编码价格表与 DB 规则优先级混乱

- **触发条件**：DB 中无匹配规则，fallback 到硬编码价格表
- **最坏结果**：价格不一致，用户困惑
- **缓解措施（编码前可做）**：
  1. 明确优先级：DB 规则 > 硬编码价格表
  2. 硬编码价格表标记为 deprecated
  3. 日志记录 fallback 行为，便于排查
- **验证方式（可执行）**：
  - 单测：`go test -run TestPriceResolutionFallback ./internal/billing/...`
  - 日志检查：grep "fallback to hardcoded price"
- **残余风险**：可接受（有日志可追踪）
