## 执行约束

- **可改文件**：
  - `core/internal/billing/*`（扩展定价子系统；保留现有 Event `Service`）
  - `core/internal/tokenusage/*`（pricing 接线、RecordUsage 字段、ephemeral schema）
  - `core/pkg/server/*`（`BillingRulesHandler`、路由/组装、增强 `CostHandler`）
  - `core/pkg/scheduler/price_table.go`（deprecated 标记 / 必要时只读 fallback）
  - `core/pkg/database/migrations/031_*`、`032_*`（新增）
  - `config/pricing/default.yaml`（新增）
  - `docs/api/`、`docs/guide/` 中计费/成本相关页（T6）
  - `docs/versions/v0.2.4/billing/*`（工作流产物）

- **不可改文件 / 禁止事项**：
  - `core/internal/auth/*`（预算/中间件不改）
  - `core/internal/proxy/*`（代理转发不改；继续走既有 TokenUsage 钩子）
  - `plugins/*`
  - 禁止新建平行路径 `/api/v1/admin/billing/costs*`
  - 禁止 rename 列 `cost_usd` / 做汇率换算
  - 禁止用现有 `billing.Service`（Event）承载定价逻辑
  - 禁止实现钱包/支付/Web 计费 UI（见方案非目标）

- **遵循规范**：`docs/harness/CONVENTIONS.md`、`docs/harness/ARCHITECTURE.md`

## 任务列表

### 任务 1：迁移脚本 + YAML 种子 + ephemeral schema 对齐

| 属性 | 值 |
|------|----|
| 功能点 | 数据模型 |
| 前置依赖 | 无 |
| 难度 | S |
| 关联风险 | R04 |
| 验收标准 | 迁移文件存在且编号为 031/032；`config/pricing/default.yaml` 可被解析；ephemeral schema 含新列的编译/单测通过 |
| 风险缓解 | 幂等迁移；minimal/ephemeral 与正式迁移字段对齐 |

**执行步骤**：

1. 新增 `config/pricing/default.yaml`（种子覆盖现网 `initDefaultPrices` 主要条目，币种 CNY）
2. 新增 `core/pkg/database/migrations/031_pricing_rules.{postgresql,sqlite}.sql`
3. 新增 `core/pkg/database/migrations/032_token_usage_billing.{postgresql,sqlite}.sql`（`input_cost`/`output_cost`/`pricing_rule_id`，无 FK）
4. 同步修改 `core/internal/tokenusage/ephemeral.go` schema，追加相同列
5. 新增 YAML 解析测试（可放在后续 T2 包内，本任务至少保证文件合法或最小 parse 测）
6. 验证：相关 `go test` 针对 database/tokenusage ephemeral 路径通过

| 功能点 | 计费规则存储 |

| 验收标准 | `go test ./core/internal/billing/... -run 'TestRuleStore\|TestYAML'` 通过 |
| 风险缓解 | 与 Event `Service` 分文件/分类型；Memory 加锁 |

**执行步骤**：

5. `yaml_loader.go`：文件加载；空库导入
6. 单测：CRUD、YAML round-trip、并发读写（Memory）
7. **禁止**：修改 `billing.Service` 的 Event 处理语义

| 功能点 | 计费规则引擎 |

| 难度 | M |
| 关联风险 | R01, R05, R06, R07 |
| 验收标准 | `go test ./core/internal/billing/... -run TestPricing` 通过 |
| 风险缓解 | 三级 fallback + InvalidateCache + Source 字段 |

**执行步骤**：

3. 缓存：TTL 默认 5 分钟；变更主动失效
4. fallback：rule → `scheduler.ModelPriceTable` → 默认 5.0/5.0 CNY
5. 单测：精确/通配/优先级/缓存失效/fallback Source
6. 确认既有 `go test ./core/pkg/server/... -run BillingHook` 仍绿

4. `price_table.go`：注释 deprecated，保留 fallback
5. 集成测：规则命中 / fallback / ephemeral 写入
6. **不改** proxy / auth

### 任务 5：管理 API（规则 + 增强既有成本接口）

| 属性 | 值 |
|------|----|
| 功能点 | 管理 API |
| 前置依赖 | T3（规则）；成本字段展示依赖 T4 完成后更有意义，可并行开发接口壳 |
| 难度 | M |
| 关联风险 | R01, R09, R11, R12 |
| 验收标准 | admin 鉴权下规则 CRUD/import/export 可用；`GET /api/v1/admin/cost/summary` 仍可用且含 `currency`；**不存在** `/admin/billing/costs*`；未授权被拒 |
| 风险缓解 | 注册 admin 组；写规则后 InvalidateCache |

**执行步骤**：

1. 新增 `core/pkg/server/billing_rules_handler.go`（或等价命名）
2. 路由：`/api/v1/admin/billing/rules` 及 import/export
3. 增强 `cost_handler.go` / `CostSummary`：增加 `currency`（默认 CNY）
4. 在 server 组装中按发行版注入 Memory/SQL RuleStore + PricingService → tokenusage
5. 测试：授权/未授权、import 后立即 Resolve、无平行 costs 路由（可用路由表断言或文档+手工）
6. **禁止**在 `core/internal/handler/` 另起一套与 server 包分裂的 admin API（与现网 CostHandler 惯例不一致）
