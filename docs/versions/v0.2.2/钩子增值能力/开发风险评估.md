## 3. Critical / High 专项

### R01 — Token 双记

- **触发条件**：钩子已记 usage，旧路径仍调用 RecordUsage
- **最坏结果**：用量/成本翻倍，配额误杀
- **缓解措施**：删除或旁路重复写入点，只保留 TriggerTokenUsedHooks
- **验证方式**：`go test` 断言单次完成请求 usage 行数 = 1
- **残余风险**：可接受（有测试门禁）

### R02 — 钩子阻断主路径

- **触发条件**：Hook 同步抛错或同步 DB 慢查询
- **最坏结果**：代理超时/5xx
- **缓解措施**：fail-open + 异步写；超时上下文
- **验证方式**：钩子返回 error 时代理仍 200 的单测
- **残余风险**：可接受（可能丢少量审计记录）

### R03 — 循环依赖

- **触发条件**：`pipeline` import `scheduler`
- **最坏结果**：无法编译
- **缓解措施**：IntentResolver 接口注入
- **验证方式**：`go test ./core/pkg/pipeline/...` 编译通过；无 pipeline→scheduler import
- **残余风险**：可接受

### R04 — 删旧遗漏

- **触发条件**：仍有 `user_request_logs` / `RequestLogService` 引用
- **最坏结果**：CI 红、运行时 nil
- **缓解措施**：`rg` 清零 + drop 迁移
- **验证方式**：`rg -n 'user_request_logs|RequestLogService' --glob '*.go'` 无业务引用
- **残余风险**：可接受

### R05 — 流式半截记录

- **触发条件**：在首个 stream chunk 即写库
- **最坏结果**：对话内容残缺
- **缓解措施**：最终聚合后写入
- **验证方式**：stream 完成路径集成/单测检查 message 完整
- **残余风险**：可接受

### R08 — Session 越权

- **触发条件**：ListSessions 未按 user 过滤
- **最坏结果**：泄露他人对话
- **缓解措施**：强制 user 作用域；team 单测
- **验证方式**：httptest 用户 A 不可见用户 B session
- **残余风险**：可接受（admin 能力若延期需文档标明）
