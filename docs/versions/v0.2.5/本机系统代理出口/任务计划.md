# 任务计划 — 本机系统代理出口

> 来源方案：`docs/versions/v0.2.5/本机系统代理出口/技术方案.md`  
> 风险评估：`docs/versions/v0.2.5/本机系统代理出口/开发风险评估.md`  
> 修订：2026-07-19（Step 2；含前端配套；**含远端/Team**）

## 执行约束

- **可改文件**：
  - `apps/proxyctl/`（新建 `centag-proxyctl`）
  - `core/internal/mitm/*`、`core/internal/pac/*`、`core/internal/cert/*`（仅本需求相关）
  - `core/pkg/config/config.go`（`SystemProxyConfig` 扩展：`listen_addr` / `advertise_host` / `allow_lan_clients`）
  - `core/pkg/server/*`（PAC 组装去写死 127.0.0.1；setup/status；config 校验）
  - `web/src/views/SystemProxy.vue`、相关 `web/src/api/*`、必要时 `Config.vue` / `Dashboard.vue`
  - `scripts/cert/*`、`scripts/ops/*`（deprecated / 端口修正）
  - `docs/guide/`、`docs/harness/INTERFACES.md`、`docs/versions/v0.2.5/本机系统代理出口/*`
  - personal 打包若需附带 `proxyctl` 的 `start.sh` / dist 说明（最小改动）

- **不可改文件 / 禁止事项**：
  - 禁止默认开启「全局代理」；禁止 **默认** MITM 非 loopback（须 `allow_lan_clients`）
  - 禁止 LAN 模式下 PAC 仍输出 `PROXY 127.0.0.1`
  - 禁止把 Host 劫持做成默认 onboarding
  - 禁止改网关执行模式语义；禁止 helper 任意 shell
  - 禁止本版本做 Clash TUN / Launcher 深度集成；禁止自动对公网暴露 MITM
  - 不改 `core/internal/auth/*`、billing、无关 migrations

- **遵循规范**：`docs/harness/CONVENTIONS.md`、`docs/harness/ARCHITECTURE.md`、`web/AGENTS.md`

## 任务列表

### 任务 T1：MITM/PAC 安全底座 + LAN/advertise 配置模型

| 属性 | 值 |
|------|----|
| 功能点 | 安全约束 + Team 远端服务端能力 |
| 前置依赖 | 无 |
| 难度 | M |
| 关联风险 | R03, R09 |
| 验收标准 | 默认 `listen_addr=127.0.0.1`、`allow_lan_clients=false`；`allow_lan_clients=false` 时拒绝非 loopback；为 true 时必须非空非 loopback `advertise_host`；`go test` 覆盖上述校验；默认 `pac_enabled=true` |
| 风险缓解 | 本机默认不暴露；Team 显式开 LAN |

**执行步骤**：

1. 扩展 `SystemProxyConfig`：`listen_addr`、`advertise_host`、`allow_lan_clients`
2. MITM 按 `listen_addr` 监听；默认 loopback
3. 配置 PUT/启动 Validate：LAN 规则见方案 §3.2
4. 单测：默认安全；LAN 开关矩阵；advertise 非法（127.0.0.1 / 空）拒绝

### 任务 T3：`centag-proxyctl`（本机 + `--server` 远端）

| 属性 | 值 |
|------|----|
| 功能点 | 客户端一键引擎（personal & team 员工） |
| 前置依赖 | T2 |
| 难度 | L |
| 关联风险 | R01, R02, R04, R05, R09 |
| 验收标准 | 子命令仅 `enable|disable|status|doctor`；`enable` 支持可选 `--server <api_base>`；远端模式：校验 status.allow_lan_clients 与 PAC PROXY 非 loopback，否则失败；`disable` 在 `client_mode=remote` 时 **不** 调用服务器关闭 MITM；snapshot round-trip；未知 argv 非零退出 |
| 风险缓解 | 白名单 CLI；远端误操作不拖垮 Team 服务 |

**执行步骤**：

1. 新建 `apps/proxyctl/`
2. snapshot 含 `client_mode` / `api_base`
3. `enable`（local）：ensure 本机 MITM + 本机 CA + 本机 PAC URL
4. `enable --server`：拉远端 status/CA；写远端 PAC URL；不启本机 MITM
5. `disable` / `doctor` 按 mode 分支
6. 单测：白名单、两模式编排（fake OS + fake HTTP）

### 任务 T4：三平台 OS 适配（代理设置 + CA 指纹装卸 + 回滚）

| 属性 | 值 |
|------|----|
| 功能点 | 跨平台一键 |
| 前置依赖 | T3 |
| 难度 | L |
| 关联风险 | R01, R02, R04, R07, R09 |
| 验收标准 | 每平台：`preseed → enable → disable → assert_restored`；远端 `enable --server` 只写客户端；CA 仅删本指纹；Linux 非 GNOME/KDE → env 降级 |
| 风险缓解 | 不破坏原 PAC；远端不误关服务器 |

**执行步骤**：

1. **macOS**：`networksetup` 自动代理；CA 按指纹删
2. **Windows**：WinINET + PAC；`certutil` 按指纹
3. **Linux**：GNOME/KDE；其它 env wrapper
4. local/remote 共用 OS 写代理原语；失败事务回滚
5. 修正旧脚本端口 8060 → 20060

### 任务 T5：前端 SystemProxy 双模式配套改造

| 属性 | 值 |
|------|----|
| 功能点 | personal 本机一键 + **team 局域网出口 / 员工连接** |
| 前置依赖 | T2, T3（T4 可并行） |
| 难度 | L |
| 关联风险 | R02, R06, R09 |
| 验收标准 | `npm run lint:ci` 通过；首屏双模式清晰；LAN 开启须确认框并配置 advertise；展示员工 PAC/CA/复制 `proxyctl enable --server …`；修 PAC URL 端口 bug；禁止把「仅开 MITM」写成「本机系统代理已配置」 |
| 风险缓解 | Team 误开 LAN 有确认；员工指引可复制 |

**页面信息架构（必须落地）**：

1. **模式切换（首屏）**
   - Tab 或分段：`本机 Centag` | `团队服务器（推荐 Team）`
2. **本机模式**
   - 一键启用/停用/诊断；安全短文；复制 `proxyctl enable`
3. **团队服务器模式（服务端管理员视图）**
   - 开关：`允许局域网客户端`（→ `allow_lan_clients`）+ 确认文案（内网风险）
   - `advertise_host` 输入（可「探测本机局域网 IP」）
   - `listen_addr`：默认建议 `0.0.0.0`（仅 LAN 开启时）
   - 只读卡片：员工 PAC URL、CA URL、指纹、`proxyctl enable --server <api>`
   - MITM 服务启停与 LAN 配置联动说明
4. **员工连接（可同页第二段或说明卡）**
   - 输入团队 API 地址 → 生成/复制客户端一键命令
   - 说明：员工 disable 只恢复自己电脑，不影响服务器
5. **高级区**：原手动向导、域名/路径表、全局模式（二次确认）
6. **修 bug**：PAC 链接用 API 口；去掉 listenPort 拼 `/api/v1/proxy/pac`
7. **Config / Host 文案**：PAC 推荐；Host 非默认
8. **API**：`getProxySetupStatus()` + 更新 config 的 LAN 字段

**执行步骤**：

1. 双模式布局落地  
2. 接 status + config 扩展字段  
3. LAN 确认流 + 员工命令生成  
4. 本机一键区 + 高级折叠  
5. `npm run lint:ci`
