## 3. Critical / High 专项

### R01 — 破坏用户原代理环境

- **触发条件**：disable 直接「关代理」而非 restore；或 snapshot 失败仍继续写。  
- **最坏结果**：公司网络/原 PAC 丢失。  
- **缓解措施**：无 snapshot 禁止改 OS；失败事务回滚；T6 往返用例。  
- **验证方式**：三平台 `preseed → enable → disable → assert_restored`。  
- **残余风险**：启用期间用户手改系统代理——停用恢复「启用瞬间」快照。可接受。

### R02 — Linux 一键夸大

- **触发条件**：统一按钮在未知 DE 上乱调配置。  
- **最坏结果**：桌面代理坏掉或无效却提示成功。  
- **缓解措施**：DE 检测；前端降级文案；env wrapper。  
- **验证方式**：GNOME + 无桌面两条路径。  
- **残余风险**：小众 DE 需手动。可接受。

### R03 — 监听面过大 / 全局代理

- **触发条件**：Addr 非 loopback；或默认全局。  
- **最坏结果**：局域网可连 MITM；全机 HTTPS 被解密。  
- **缓解措施**：T1 强制；UI 二次确认。  
- **验证方式**：单测 + T6 勾选。  
- **残余风险**：用户主动开全局。可接受。

### R04 — CA 误删 / 残留

- **触发条件**：按 CN 模糊删除；停用不卸 CA。  
- **最坏结果**：误伤其它 CA 或长期残留信任。  
- **缓解措施**：指纹；默认卸；doctor。  
- **验证方式**：安装前后证书库对比。  
- **残余风险**：用户勾选保留 CA。可接受。

### R05 — helper 提权滥用

- **触发条件**：helper 接受任意 argv 拼 shell。  
- **最坏结果**：本地提权跳板。  
- **缓解措施**：子命令枚举；单测拒未知 flags。  
- **验证方式**：T3 单测。  
- **残余风险**：可接受。

### R09 — Team 局域网出口误配

- **触发条件**：默认绑 0.0.0.0；或 LAN 开了但 PAC 仍 `PROXY 127.0.0.1`；或员工 disable 关掉服务器 MITM。  
- **最坏结果**：内网被滥用 MITM / 员工永远连不上 / 全队出口中断。  
- **缓解措施**：默认 loopback；LAN 显式+确认；advertise 强制；`client_mode=remote` 的 disable 只动客户端。  
- **验证方式**：T2 PAC 断言 + T6 两机用例。  
- **残余风险**：管理员主动对公网暴露——文档禁止，产品不做自动暴露。可接受。
