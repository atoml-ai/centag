# 技术方案 — 商业化分层（插件式 Open Core）

> 版本：v0.2.7 | 日期：2026-07-20  
> 修订：2026-07-20 — **目标态**：开源仅 minimal/personal；Team 主程序与插件在 `centag-pro`；开源删除 `dist/team`

## 1. 背景与目标

### 1.1 目标

| 原则 | 含义 |
|------|------|
| 开源自立 | `minimal` / `personal` 源码、依赖、构建、CI **零**接触 `centag-pro` |
| 商业扩展 | Team（及未来 Enterprise）= 开源核心 + **pro 插件包**，仅构建商业 SKU 时引入 |
| 插件接入 | pro 内功能以 `extension.Plugin` +（前端）Web Pack 注册 |
| 缺 pro 失败 | 指定 team 但无 pro → **构建失败**，不产出残缺二进制 |

### 1.2 非目标（本阶段）

- E0/E1 **不**完成存量多租户代码整包迁出（E2+）
- E0/E1 **不**完成 team 前端 pack 迁出（E3）
- 不把计费规则查看等 personal 已用能力迁入 pro

### 1.3 仓库与依赖方向

```text
centag (OSS)                         centag-pro (private)
├── dist/minimal|personal              ├── cmd/centag-team     ★ Team main
├── core/pkg/extension  Host           ├── bundle/team         SKU 组合
├── core/pkg/{authapi,…} 原语 facade   ├── plugins/team       注册 + license
├── core/pkg/editionmodule             ├── internal/teamadmin ★ Team 产品实现
├── web/ (personal/minimal)            └── web/packs/*         前端包（E3）
└── start.sh：仅 minimal/personal（拒绝 build/debug team）
```

**依赖边：仅 `centag-pro → centag`。开源模块图无私有边。**

**分支同步（强制）：** `centag-pro` 与 `centag` **使用相同分支名**（如双方均为 `feature/v0.2.7`），随主仓开分支/合并/打 tag 对齐。`build-team.sh` 检测不一致并警告；`CENTAG_PRO_STRICT_BRANCH=1` 时构建失败。

## 2. 方案选型

| 方案 | 说明 | 结论 |
|------|------|------|
| A：开源 `dist/team` require pro | 开源出现私有边 | 否 |
| B：开源 stub + overlay | 假 team 壳，切分不干净 | 否（已废弃） |
| **C：Team main 在 pro；开源删 dist/team** | 完美切分；开源不提供 build team 入口 | ⭐ |

## 3. 详细设计

### 3.1 后端 Extension Host

- 包：`centag/core/pkg/extension`
- `Plugin`：`Name()` + `Init(Host)`
- `Host`（E2.0 已落地）：`Edition()`、`Deps()`、`RegisterTeamAdmin` / `RegisterUserAPI` / `RegisterSystemAPI`、`RegisterProtectedMiddleware`、`RegisterBillingHook`
- 实现：`RuntimeHost` 在 Server deps 就绪后 `InitAll`，于 `setupRoutes` 落盘（R13）
- 商业包 `init()` → `extension.Register`；team 二进制 blank-import `bundle/team`
- 并存：`editionmodule` 继续承载 admin 增量路由（`/api/v1/admin/pro`）；存量产品 API 不改路径

### 3.2 Team 构建

| 入口 | 行为 |
|------|------|
| `centag-pro/./start.sh build team` | **唯一** Team 构建入口 → `bin/centag-team`（对齐开源用法） |
| `centag-pro/./start.sh build fe\|all` | Team 前端 pack / 全量 |
| `centag/start.sh build\|debug team` | **拒绝**并提示改到 pro（不再转调） |
| `start.sh` Docker team | 拒绝并提示改在 pro 构建 |

### 3.3 前端（E3）

- 开源 `web/` = Host；默认 `@team-pack` → 空 stub（personal/minimal 无 team 页面 chunk）
- pro `web/packs/team` = 商业页；`./start.sh build fe`（转调 `scripts/build-web-team.sh`）注入构建
- D1：`/cost` 留 Host，不在 TEAM_ONLY

### 3.4 能力迁移节奏

| 阶段 | 内容 |
|------|------|
| **E0** | Host SDK + 单测 |
| **E1** | pro `cmd/centag-team` + bundle；开源删 `dist/team`；开源拒绝 build team |
| **E2** | 迁 team 后端产品代码进 `plugins/team` |
| **E3** | 迁 team Web 进 packs |
| **E4** | CI 双轨 + 第二插件空壳证明扩展路径 |

## 4. 兼容性

- personal / minimal：行为与构建路径不变（无 pro）
- 原开源 `dist/team`：删除；文档与脚本指向 pro
- 存量 `CENTAG_EDITION=team` 运行时能力：E2 前仍主要在开源核心；E2 后由插件承载产品面

## 5. E2 迁出边界（摘要）

> 明细与任务见 `任务计划.md`。**D6（2026-07-21）**：Team **产品实现**必须在 `centag-pro`；开源禁止 `pkg/teamadmin` 类产品包。

| 迁出 → pro（**实现 + 注册**） | 留开源（原语 / personal） |
|------------|--------|
| Admin users、代管 API Keys、Tenants、QuotaMW、Admin usage/quotas | 认证、profile、自管 Key、用户 token-usage |
| Provisioner、BillingHook、system update、AB Admin API | cost/summary、billing/rules |
| | backends/pipelines/对话 Store、TenantID、DB schema、AB Persist 钩子 |
| | Host 原语：`authapi` / `tokenusageapi` / `billingasync` / `quotaapi` / `agentapi` / `abevalapi` / `systemupdateapi` |
| | useraccess（本波留开源，仅 `IsTeam` 生效） |

**路径策略**：存量 API **不改路径**；经 `extension.Host` 挂载。

**Go internal 解锁**：开源抬升最小 `pkg/*` facade；pro **零** `import centag/core/internal`。
