# 任务计划 — 商业化分层（Open Core）

> 来源方案：`docs/versions/v0.2.7/commercialization-layered/技术方案.md`
> 风险评估：`docs/versions/v0.2.7/commercialization-layered/开发风险评估.md`
> 版本：v0.2.7 | 日期：2026-07-20 | 作者：Hermes Agent

## 执行约束

- **可改文件**（开源仓 `centag`）：
  - `dist/team/` 下新增 build-tag 隔离的 business 接线文件（`team_business.go` / `team_business_stub.go`）
  - `LICENSE`（核心仓协议声明为 MIT）
  - `docs/`（文档与 README 补充说明）
- **可改文件**（闭源仓 `centag-business`，新建私有仓）：
  - `go.mod`、`main` 注册入口、`router/`、`optimizer/` 等业务插件包
  - 多租户/策略/第三方对接相关实现
- **不可改文件**：
  - `core/internal/`（核心内部实现，team 增值不得反向依赖或新增专有逻辑，见 R03）
  - `dist/personal/main.go`、`dist/minimal/main.go`（保持免费版不变）
  - `web/src/views/` 下的 team 路由骨架（复用既有，仅由后端 capability 激活）
- **遵循规范**：`docs/harness/ARCHITECTURE.md`、`docs/harness/CAPABILITY_BOUNDARY.md`、`docs/guide/external-business-plugins.md`

## 开发风险与任务映射

| 风险 ID | 等级 | 归属任务 | 验收如何覆盖 |
|---------|------|----------|--------------|
| R01 | High | T1 | 开源构建（无 `business_team` tag）`go build ./dist/team` 成功且不含私有代码 |
| R02 | High | T2 | 闭源仓 `go.mod` 锁定核心版本；双向 CI 绿 |
| R03 | Critical | T3 | `rg "centag-business" core/` 为空；核心零新增 team 专有逻辑 |
| R04 | Medium | T4 | personal 下 `/tenants` 路由 403/不可达 |
| R05 | High | T5 | LICENSE = MIT；`grep -i "GPL\|AGPL" LICENSE` 为空 |
| R06 | Medium | T6 | 闭源仓不含单租户额度/计量重复实现 |
| R07 | Medium | T7 | 核心仓无 license 校验代码（`rg "license" core/internal/` 为空） |
| R08 | Low | T8 | 闭源仓 README + 验证脚本存在 |

> High 必须全部映射；Critical 开放数必须为 0（R03 已缓解，残余可接受）。

## 任务列表

### 任务 1：开源仓 team 发行版 business 接线隔离（T1）

| 属性 | 值 |
|------|----|
| 功能点 | 跨仓接线隔离（方案 §3.1） |
| 前置依赖 | 无 |
| 难度 | S |
| 关联风险 | R01 |
| 验收标准 | `go build -tags '' ./dist/team` 成功；`rg -l "centag-business" dist/team/` 在无 tag 构建下为空 |
| 风险缓解 | 用 `//go:build business_team` 与 `//go:build !business_team` 双文件隔离；默认开源构建走 stub |

**执行步骤**：
1. 在 `dist/team/` 新建 `team_business_stub.go`：`//go:build !business_team`，同 `package main`，空 `init()` 或仅引入核心（不含私有 import）。
2. 新建 `team_business.go`：`//go:build business_team`，内含 `_ "github.com/atoml-ai/centag-business/..."` blank import（闭源仓路径，待 T2 确立）。
3. `go build -tags '' ./dist/team` 验证默认构建成功。
4. `rg -l "centag-business" dist/team/` 在无 tag 下应为空。

---

### 任务 2：建立闭源仓 centag-business 脚手架（T2）

| 属性 | 值 |
|------|----|
| 功能点 | 闭源增值仓初始化（方案 §2.2 / §3.1） |
| 前置依赖 | T1（确认模块路径） |
| 难度 | M |
| 关联风险 | R02、R06 |
| 验收标准 | 闭源仓 `go build ./...` 成功；`go.mod` 含 `replace centag => <核心仓本地/私有路径>` 指向具体版本 |
| 风险缓解 | `go.mod` 锁定核心仓 commit/tag；目录结构按 external-business-plugins.md 规范；不重复实现单租户能力 |

**执行步骤**：
1. 新建私有仓 `github.com/atoml-ai/centag-business`，初始化 `go.mod`（module 路径同上）。
2. 在 `go.mod` 添加 `require centag v0.2.7` + `replace centag => <核心仓路径>`，锁定具体 commit。
3. 按 `docs/guide/external-business-plugins.md` 建立插件注册骨架：`register.go` 内含 `init()` 调用 `business.Register()`。
4. `go build ./...` 验证；建立双向 CI（核心新 tag 触发闭源仓构建）。

### 任务 3：team 多租户/多用户管理增值（T3）

| 属性 | 值 |
|------|----|
| 功能点 | 多用户/多租户管理（用户决策第 1 点） |
| 前置依赖 | T2 |
| 难度 | L |
| 关联风险 | R03、R06 |
| 验收标准 | 闭源仓实现经 `business.Register()` / 管理接口接入；`rg "centag-business" core/` 为空；多租户 CRUD 单测通过 |
| 风险缓解 | 仅经 BusinessPlugin + `/api/v1/admin/*` 扩展点；复用核心 `RegisterForTenant`、`team_quota_service`；不修改 `core/internal/` |

**执行步骤**：
1. 在闭源仓实现租户 CRUD、子用户、角色权限（经管理接口暴露，按 ARCHITECTURE 允许）。
2. 复用核心 `RegisterForTenant`（多租户流水线隔离）与 `team_quota_service`（租户额度）。
3. 不向 `core/internal/` 写入任何 team 专有逻辑。
4. 单测覆盖租户创建/隔离/子用户权限。
