## 3. Critical / High 专项

### R01 — 自动发现误收录

- **触发条件**：流水线含多个无 route_config 的 generator，且未声明 slots  
- **最坏结果**：用户误改非路由节点模型  
- **缓解措施（编码前可做）**：发现算法白名单写入技术方案并单测锁定  
- **验证方式**：对 fixture（router-only / 杂散 generator）跑发现单测，断言 node 集合  
- **残余风险**：可接受  

### R02 — coding 多阶段回归

- **触发条件**：用户沿用库内旧单节点 `coding-agent`，或客户端假设单模型  
- **最坏结果**：阶段路由不符合预期；工具调用仅在 implement  
- **缓解措施**：README/代理模式文档说明升级方式；default_route → implement；保留 tool prompt  
- **验证方式**：手工/脚本对「架构」「写代码」「review」「单测」四类输入检查命中节点（日志或执行记录）  
- **残余风险**：可接受（不自动改用户库）  

### R03 — 双轨逻辑

- **触发条件**：同时保留 routeModelAssign 与 capabilitySlots 且行为分叉  
- **最坏结果**：修一处漏一处  
- **缓解措施**：Step 3 以单一模块为准；旧文件删除或 re-export  
- **验证方式**：`rg routeModelAssign` 仅剩兼容层或零命中  
- **残余风险**：可接受  

### R08 — 配置模型 vs 加分类职责

- **触发条件**：在配置模型弹窗内做 routes CRUD  
- **最坏结果**：与画布状态不一致、排期膨胀  
- **缓解措施**：G5 明确拓扑只在画布「新增分类」+ router 抽屉；配置模型只绑模型  
- **验证方式**：CR：CapabilitySlotsDialog 无 routes 编辑  
- **残余风险**：可接受  

### R11 — 新增分类向导写图不一致

- **触发条件**：只加了节点未写 routes，或 route_value 与 routes key 不一致；或新关键词覆盖旧路由  
- **最坏结果**：请求永不命中新分类 / 旧分类失效  
- **缓解措施**：向导提交检查清单；单元测断言三处同时更新；关键词冲突抛错拒绝覆盖  
- **验证方式**：selftest（含关键词已存在）；手工加分类后发关键词命中（可选联调）  
- **残余风险**：可接受
