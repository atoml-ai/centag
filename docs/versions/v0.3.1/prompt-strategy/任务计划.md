## 任务列表

### 任务 1：System 策略框架与双路径接线（A0）

| 属性 | 值 |
|------|----|
| 功能点 | F1 |
| 前置依赖 | 无 |
| 难度 | L |
| 关联风险 | R01, R04, R09 |
| 验收标准 | 1) 存在 `core/pkg/pipeline/promptstrategy`（或等价）含 `passthrough\|append\|replace` 与兼容映射；2) `transparent_forward` 与 `generator`（含 stream）均调用同一 Apply；3) `go test ./core/pkg/pipeline/... -count=1` 相关用例绿，含 append 与 Responses fail-open；4) `#t` 透传 / `#d` replace 契约不回归 |
| 风险缓解 | 消灭双份 inject 逻辑；Responses 安全优先 |

**执行步骤**：

1. 新建算子包：枚举、`ResolveSystemMode(injectBool, strategy)`、`ApplySystemStrategy`、可选轻量模板渲染对齐。  
2. 改造 `injectSystemPromptIntoChatBody` 为薄封装或直接换用 Apply（含 append）。  
3. Generator 非流式/流式路径同步。  
4. 扩展 `transparent_forward_node_test.go`、`mode_templates_contract_test.go`。  
5. `go test ./core/pkg/pipeline/... -count=1`。

### 任务 2：user_prompt_ops 入站节点（A1）

| 属性 | 值 |
|------|----|
| 功能点 | F2 |
| 前置依赖 | 任务 1（至少 body sync helper 可用） |
| 难度 | M |
| 关联风险 | R02, R06, R07, R10 |
| 验收标准 | 1) 节点可注册执行；2) 改 last user 后 `raw_request_body` 同步；3) `on_hit=block` 不发起后端；4) 日志脱敏；5) 单测覆盖 redact/truncate/block |
| 风险缓解 | 透传路径必测 body；默认非误 block |

**执行步骤**：

1. 实现规则检查（关键词/密钥启发式）+ 截断/空白折叠。  
2. 实现 `SyncChatBodyMessages`（或并入 promptstrategy）。  
3. 注册 NodeType / schema / 引擎映射。  
4. 单测 + 带 raw body 的集成断言。  
5. `go test ./core/pkg/pipeline/... -run UserPrompt -count=1`（或全量 pipeline）。

### 任务 3：output_post_ops 出站后处理节点（A2）

| 属性 | 值 |
|------|----|
| 功能点 | F3 |
| 前置依赖 | 无（可与 T2 并行；建议 T1 后） |
| 难度 | M |
| 关联风险 | R03, R10 |
| 验收标准 | 1) 支持 trim / strip_fence / extract_json / json_compact；2) 非流式默认生效；3) 流式默认 skip；4) buffer 模式有 max 限制单测；5) 复用或抽取 `cleanJSONContent` |
| 风险缓解 | 默认不缓冲流式，防 OOM |

**执行步骤**：

1. 实现算子链与节点 Execute。  
2. 注册与 schema。  
3. 单测 JSON fence 与 stream skip。  
4. `go test ./core/pkg/pipeline/... -run OutputPost -count=1`。
