## 3. Critical / High 专项

### R01 — 双路径 system 语义漂移

- **触发条件**：forward 与 generator 各自实现 append/replace，或仅一边接新字段。
- **最坏结果**：同一 YAML 字段在不同模式行为不同，线上难排查。
- **缓解措施（编码前）**：算子单测为真源；节点层只做「取配置 → 调算子 → 写回」。
- **验证方式**：`go test ./core/pkg/pipeline/... -count=1` 含策略矩阵；`rg -n "injectSystemPromptIntoChatBody|ApplySystemStrategy" core/pkg/pipeline` 确认无平行旧逻辑残留（旧函数可薄封装转调）。
- **残余风险**：可接受（测试覆盖）。

### R02 — raw_request_body 未同步

- **触发条件**：`user_prompt_ops` 或 system 策略只改结构化 Messages。
- **最坏结果**：透明/直连仍把客户端原文打到后端，策略形同虚设。
- **缓解措施**：所有改写出口强制经过 body sync；无 body 时仅改 Messages（WebUI 最小 body 路径另测）。
- **验证方式**：构造带 `raw_request_body` 的 NodeInput，执行后 `json.Unmarshal` 断言 messages；契约/集成测试覆盖 `#t`。
- **残余风险**：可接受。

### R03 — 流式 buffer 性能

- **触发条件**：默认开启 buffer 或未限制大小。
- **最坏结果**：网关 OOM / 客户端超时。
- **缓解措施**：默认 skip；buffer 需配置且 `max_buffer_bytes` 封顶，超限 fail-open 透传剩余。
- **验证方式**：单测模拟超限；文档声明默认行为。
- **残余风险**：可接受。

### R04 — Responses 误改

- **触发条件**：在 Responses 体上套用 chat-only inject 逻辑。
- **最坏结果**：桥接失败或客户端协议错误。
- **缓解措施**：保持「responses_to_chat 先于 system 策略」；无法识别则 skip；专用测试（已有 inject+responses 用例可扩展）。
- **验证方式**：扩展 `transparent_forward_node_test.go` Responses 用例。
- **残余风险**：可接受（Phase A Responses append 能力有限）。

### R07 — 日志泄密

- **触发条件**：Info 日志打印完整 prompt。
- **最坏结果**：密钥进日志系统。
- **缓解措施**：统一 Mask；命中规则只记 pattern id / 原因码。
- **验证方式**：单测 hook logger 或检查格式化辅助函数；`rg` 审查新日志字段。
- **残余风险**：可接受。

### R08 — 范围膨胀到 LLM 实装

- **触发条件**：实现中直接调用后端做预检。
- **最坏结果**：延迟/费用/排期失控，阻塞 v0.3.1。
- **缓解措施**：任务计划将 B2 标为非本版；接口 Null 实现；Code Review 拒绝核心内嵌厂商调用。
- **验证方式**：任务计划验收清单；`rg` 确认无 Phase A 真实 LLM preprocess 调用。
- **残余风险**：可接受。

### R13 — Web 未交付无法验收

- **触发条件**：只合后端/YAML，抽屉仍只有旧布尔开关或无法添加 User/Output 节点。
- **最坏结果**：无法按操作说明做手工联调，需求无法闭环。
- **缓解措施**：A4 列为 Phase A 必做；与后端同里程碑；出口含浏览器五步。
- **验证方式**：按 `前端配置操作说明.md` §10 走通；`web` 下 `npm run lint:ci`。
- **残余风险**：可接受。

### R14 — Web/后端字段双写不一致

- **触发条件**：前端继续只写 `inject_system_prompt`，后端已读 `system_prompt_strategy`（或相反）。
- **最坏结果**：UI 显示与真实行为不符。
- **缓解措施**：读写映射表与后端兼容规则一致；保存后刷新抽屉回读。
- **验证方式**：改策略→保存→重新打开节点，字段与页面行为一致；可选组件/自测脚本。
- **残余风险**：可接受。
