# Centag 能力边界矩阵

> 本文档定义核心层、流水线层、插件层的能力划分与扩展点。
> 是架构决策的"判断手册"——新功能该放哪层，查此文档。

---

## 1. 三层架构总览

```
┌─────────────────────────────────────────────────────────┐
│  核心层 (internal/)                                      │
│  协议翻译 + 请求编排 + 基础设施                            │
│  原则：不含业务逻辑，不含具体技术实现                       │
├─────────────────────────────────────────────────────────┤
│  流水线层 (internal/pipeline/)                           │
│  处理链编排 + 节点调度                                     │
│  原则：节点通过 CapabilityBroker 调用能力                  │
├─────────────────────────────────────────────────────────┤
│  插件层 (plugins/)                                       │
│  具体实现（协议/后端/存储/业务）                            │
│  原则：通过接口契约与核心交互，init() 注册                  │
└─────────────────────────────────────────────────────────┘
```

## 3. 扩展点

| 扩展点 | 接口 | 注册方式 | 位置 |
|--------|------|---------|------|
| 新协议 | `ProtocolPlugin` | `plugin.RegisterProtocol()` | `plugins/protocol/` |
| 新后端 | `BackendPlugin` | `plugin.RegisterBackend()` | `plugins/backend/` |
| 新存储 | `StoragePlugin` | `storage.RegisterPlugin()` | `plugins/storage/` |
| 新流水线节点 | `NodePlugin` | `node.Register()` | `internal/pipeline/nodes/` |
| 新业务插件 | `BusinessPlugin` | `business.Register()` | `plugins/business/` |
| 新代理模式 | 模板配置 | `config/initdata/pipeline-templates/` | YAML 配置 |

## 4. 边界判断决策树

```
新功能该放哪层？

Q1: 这是所有 LLM 网关都需要的基础能力吗？
    ├── 是 → 核心层 (internal/)
    └── 否 → Q2

Q2: 这是一个可编排的处理步骤吗？
    ├── 是 → 流水线节点 (internal/pipeline/nodes/)
    └── 否 → Q3

Q3: 这是某个具体技术/厂商的实现吗？
    ├── 是 → 插件 (plugins/)
    └── 否 → 不做，或通过配置表达
```

## 5. 示例判断

| 场景 | 归属 | 理由 |
|------|------|------|
| 接收 HTTP 请求 | 核心层 | 所有网关都需要 |
| 解析 `X-Proxy-Mode` 头 | 核心层 | 代理模式是核心概念 |
| 调用 OpenAI API | 插件 | 具体厂商实现 |
| 缓存精确匹配 | 流水线节点 | 可选处理步骤 |
| 用户额度检查 | 核心层 | 多用户管理是基础能力 |
| 内容安全审核 | 流水线节点 | 可选、可配置 |
| 记忆存储 | 流水线节点 | 通过 CapabilityBroker |
| Redis 存储实现 | 插件 | 具体技术实现 |
| 成本分析 | 核心层 (tokenusage) | 基础计费能力 |
| 计费策略（按用户/团队） | 核心层 | 团队管理基础能力 |
| Prometheus 指标暴露 | 核心层 | 运维基础 |
| 调度决策日志 | 核心层 | 诊断基础 |
| 请求日志存储 | 核心层 | 审计基础 |
| A/B 测试 | 流水线节点 | 可选、可配置 |
| 模型路由分类 | 流水线节点 | `builtin.router` |

## 6. 约束

- 核心层 **不能** 引用插件层（只能通过接口）
- 插件层 **不能** 引用核心层的内部实现
- 流水线节点 **必须** 通过 CapabilityBroker 访问外部能力
- 所有扩展 **必须** 通过 `init()` 注册，支持 `_ import`
- 垂直领域能力 **必须** 通过 Pipeline 模板暴露，不新增业务路由
