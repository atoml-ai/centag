# Phase 2: 任务规划（Step 2）

> 快捷别名：`step2-plan` / 任务规划 / 拆任务 / step2

## 目标

将技术方案拆解为有序、可执行的开发任务计划，并把开发风险落到具体任务。

## 前置门禁

Gate 1（技术方案落盘 + **开发风险评估落盘** + 内审 Critical = 0 + 人工确认）

> ⚠️ 执行前必须先检查 Gate 1，未通过则拒绝继续。  
> 缺少 `开发风险评估.md` 时引导 `step1-risk`，禁止直接拆任务。

## 执行清单

### 1. 读取输入

- [ ] 读取技术方案（`docs/versions/<版本>/<需求>/技术方案.md`）
- [ ] 读取开发风险评估（`docs/versions/<版本>/<需求>/开发风险评估.md`）
- [ ] 理解功能点清单和依赖关系
- [ ] 确认用户角色和关注范围

### 2. 任务拆解

- [ ] 从方案中提取功能点清单
- [ ] 将每个功能点拆解为独立任务
- [ ] 标注任务间的依赖关系
- [ ] 建议执行顺序
- [ ] High 风险全部映射到任务 ID

### 3. 编写任务计划

- [ ] 每个任务包含：
  - 任务名称与描述
  - 所属功能点
  - 前置依赖
  - 可执行验收标准（必须是可验证的动作）
  - 执行约束（可改/不可改文件清单）
  - 关联风险 ID + 缓解要点
- [ ] 含「开发风险与任务映射」表
- [ ] 计划写入 `docs/versions/<版本>/<需求>/任务计划.md`
- [ ] 回写 `开发风险评估.md` 归属任务与状态

### 4. 人工确认

- [ ] 用户确认任务计划
- [ ] 用户确认执行顺序
- [ ] 用户确认风险映射完整

## 产出

| 产物 | 路径 |
|------|------|
| 任务计划 | `docs/versions/<版本>/<需求>/任务计划.md` |
| 开发风险评估（更新） | `docs/versions/<版本>/<需求>/开发风险评估.md` |

## 完成后

- 更新 `workflow_state.md`：Step 2 → ✅，Gate 2 → ✅
- 提示用户可执行 `step3-code` 进入编码实现阶段（将自动检查 Gate 2）
