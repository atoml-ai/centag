# Phase 4: 质量交付（Step 5）

> 快捷别名：`step5-review` / CR / 代码审查 / 自测 / step5

## 目标

自测验证 + 代码审查 + 人工复核 + 产物检查。

## 前置门禁

Gate 3（全量测试通过 + 覆盖率达标 + lint 无新增）

> ⚠️ 执行前必须先检查 Gate 3，未通过则拒绝继续。

## 执行清单

### 1. 自测验证

- [ ] 对照任务计划的验收标准，逐项验证
- [ ] 运行全量测试：`go test ./...`
- [ ] 运行 lint：`make lint`
- [ ] 运行卫生检查：`make harness-check`
- [ ] 验证 API 行为（若有接口变更）：`curl http://localhost:20060/api/...`
- [ ] 按 `docs/harness/templates/自测记录模板.md` 将验证过程和结果写入自测记录

### 2. 代码审查

- [ ] 对照 ANTI-PATTERNS.md 检查是否存在反模式
- [ ] 检查架构合规性（分层、依赖方向）
- [ ] 检查代码规范符合性（命名、错误处理、注释）
- [ ] 检查测试覆盖是否充分
- [ ] 按 `docs/harness/templates/CR_报告模板.md` 输出 CR 报告
- [ ] 识别 Critical 问题并修复（目标：Critical = 0）

### 3. 产物完整性检查

- [ ] 技术方案已落盘
- [ ] 任务计划已落盘
- [ ] 自测记录已落盘
- [ ] CR 报告已落盘
- [ ] 代码 + 测试已就绪

### 4. 人工复核

- [ ] 用户复核代码变更
- [ ] 用户确认产物完整性
- [ ] 用户确认可交付

## 产出

| 产物 | 路径 |
|------|------|
| 自测记录 | `docs/versions/<版本>/<需求>/自测记录.md` |
| CR 报告 | `docs/versions/<版本>/<需求>/CR_报告.md` |
| 代码 + 测试 | 对应 `internal/` / `plugins/` 目录 |

## 完成后

- 更新 `workflow_state.md`：Step 5 → ✅，Gate 3 → ✅，Gate 4 → ✅
- 确认 Gate 4 准出条件全部满足
- 提示用户可进行合并或部署
