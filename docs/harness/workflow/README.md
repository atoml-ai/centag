# 统一研发工作流

> Spec-Driven Development — 代码不是共识，Spec 才是共识。

## 概述

本工作流将研发过程统一为 **4 个阶段、5 个步骤、4 道门禁**，覆盖从方案设计到质量交付的完整链路。

### 设计原则

| 原则 | 说明 |
|------|------|
| **Spec 先行** | 技术方案 → 任务计划 → 代码，每步产出即为下一步的执行依据 |
| **Spec 驱动编码** | 编码严格依据技术方案实现，测试验证 Spec 合规性 |
| **门禁硬约束** | 每个 Phase 有准出门禁，跨 Phase 时自动检查，未通过禁止继续 |
| **产物全落盘** | 所有产物有标准路径和格式，可追溯、可审计 |
| **小步修改** | 每次改动范围可控，新增行为配测试，不放大修改范围 |

## 工作流全景

```
Phase 1              Phase 2             Phase 3              Phase 4
方案设计              任务规划             编码实现              质量交付
──────────           ──────────          ──────────           ──────────

Step 1: 方案设计      Step 2: 任务规划     Step 3: SDD 编码      Step 5: CR 审查
  与确认             (拆解+执行计划)         实现

                                           Step 4: 单元测试
                                              补全

──────────           ──────────          ──────────           ──────────
     GATE 1 ──────→     GATE 2 ────────→     GATE 3 ──────→     GATE 4
                                                              (交付准出)
```

## 阶段详情

| 阶段 | 步骤 | 核心目标 | 主要产出 |
|------|------|---------|---------|
| **Phase 1** 方案设计 | Step 1: 方案设计与确认 | 方案多轮推敲 + AI 内审 + 人工确认 | 技术方案 |
| **Phase 2** 任务规划 | Step 2: 任务规划 | 方案拆解为任务 + 编码级步骤细化 | 任务计划 |
| **Phase 3** 编码实现 | Step 3: SDD 编码实现 | 按 Spec 编码，测试验证合规 | 代码 + 测试 |
| | Step 4: 单元测试补全 | 补充边界/异常/安全测试 | 补充测试 |
| **Phase 4** 质量交付 | Step 5: CR 审查 | 自测 + 审查 + 人工复核 + 产物检查 | 自测记录 + CR 报告 |

## 快捷别名

用户可通过别名直接触发对应步骤，AI 自动加载对应指引并检查前置门禁：

| 别名 | 步骤 | 前置门禁 |
|------|------|---------|
| `step1-design` / 方案设计 | Step 1: 方案设计与确认 | 无 |
| `step2-plan` / 任务规划 | Step 2: 任务规划 | Gate 1 |
| `step3-code` / 编码 | Step 3: SDD 编码实现 | Gate 2 |
| `step4-test` / 补测试 | Step 4: 单元测试补全 | 无（同 Phase） |
| `step5-review` / CR / 代码审查 | Step 5: CR 审查 | Gate 3 |

## 门禁链

| 门禁 | 位置 | 核心条件 | 触发时机 |
|------|------|---------|---------|
| Gate 1 | Phase 1 → 2 | 技术方案落盘 + 内审 Critical = 0 | `step2-plan` |
| Gate 2 | Phase 2 → 3 | 任务计划落盘 + 可执行验收标准 | `step3-code` |
| Gate 3 | Phase 3 → 4 | 全量测试通过 + 覆盖率达标 + lint 无新增 | `step5-review` |
| Gate 4 | 交付准出 | CR Critical = 0 + Spec 合规 + 产物齐全 | CR 完成时 |

## 产物路径

```
docs/versions/<版本>/<需求>/
├── 技术方案.md              ← Step 1
├── 任务计划.md              ← Step 2
├── 自测记录.md              ← Step 5
└── CR_报告.md               ← Step 5
```
