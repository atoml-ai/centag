# Step 2: 任务规划

> 执行指南：`docs/harness/workflow/phase-2-plan.md`

## 触发词

`step2-plan` / 任务规划 / 拆任务 / 拆解 / step2

## 前置门禁

**Gate 1**：技术方案落盘 + 内审 Critical = 0

> ⚠️ 执行前必须先检查 Gate 1，未通过则拒绝继续。

## 执行流程

### 第一步：收集输入

1. 确认当前需求名称
2. 读取技术方案（`docs/versions/<版本>/<需求>/技术方案.md`）
3. 阅读 `docs/harness/ARCHITECTURE.md` 了解模块影响范围
4. 确认用户角色和关注范围

### 第二步：任务拆解

1. 从技术方案中提取功能点清单
2. 将每个功能点拆解为独立任务
3. 标注任务间的依赖关系
4. 确定执行顺序

### 第三步：编写任务计划

按 `docs/harness/templates/任务计划模板.md` 结构编写，每个任务包含：

- 任务名称与描述
- 所属功能点
- 前置依赖
- **可执行验收标准**（必须是可验证的动作，如 `go test ./...`、`curl 验证`等）
- **执行约束**（可改/不可改的文件清单）
- 风险提示

写入 `docs/versions/<版本>/<需求>/任务计划.md`

### 第四步：人工确认

- 用户确认任务计划
- 用户确认执行顺序
