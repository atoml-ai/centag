# Centag

[English](README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Русский](README.ru.md) | [Español](README.es.md)

**Локальное подключение прокси в один шаг** для coding-агентов, **единое управление** бэкендами и API-ключами, плюс **настраиваемые действия прокси** под сценарий (переключение, отказоустойчивость, пайплайны)—без отдельной настройки каждого инструмента.

Для индивидуальных разработчиков: установить Centag → подключить агента через wrap или конфиг → управлять бэкендами и политиками в Web UI.

## Установка

Выберите один способ. После установки запустите `centag` и откройте **http://localhost:20060**.

### Способ 1: скрипт в одну строку (рекомендуется, Node.js не нужен)

```bash
curl -fsSL https://raw.githubusercontent.com/atoml-ai/centag/main/scripts/install.sh | bash
```

По умолчанию ставится в `~/.centag/` и по возможности добавляется в PATH. Далее: `centag` / `centag wrap`.

### Способ 2: npm (если уже есть Node.js)

```bash
# Глобальная установка (онлайн-пакет; бинарник с GitHub Releases)
npm install -g @atomlai/centag

# Или попробовать без изменения глобальных путей
npx --yes @atomlai/centag

# Офлайн / закрытая сеть
npm install -g @atomlai/centag-offline
```

При ошибке прав на `npm install -g` используйте `npx` или скрипт выше. Подробнее: [apps/centag-npm/README.md](apps/centag-npm/README.md).

### Способ 3: Docker (из исходников)

```bash
git clone https://github.com/atoml-ai/centag.git
cd centag
cp config/secrets/.env.example config/secrets/.env   # при необходимости отредактируйте
./start.sh docker up                                 # по умолчанию: personal
```

Админка там же: http://localhost:20060. Остановка: `./start.sh docker down`.

## После установки: подключение агента

Цель: пользоваться агентом как обычно, а трафик направлять через Centag (общие бэкенды, failover, учёт).

1. **Откройте Web** → добавьте и включите хотя бы один бэкенд (API-ключ или локальный совместимый endpoint).
2. **Подключение Agent** (меню Web) — мастер создаст/запишет конфиги; или
3. **Процессный прокси (рекомендуется — минимум правок агента)**:

```bash
# При уже запущенном локальном Centag
centag wrap run -- opencode
# замените opencode на команду запуска вашего агента

# Проверка
centag wrap doctor
```

Важно: `centag wrap` **не** поднимает шлюз — только направляет трафик процесса агента в уже работающий Centag. Полное руководство: [system proxy egress](docs/guide/system-proxy-egress.md).

## Почему Centag

| Что нужно | Что делает Centag |
|-----------|-------------------|
| **Быстрое переключение бэкендов** | Единое управление; включение/смена в Web без перенастройки каждого агента |
| **Авто-failover + пул API-ключей** | Ротация ключей; переключение при лимитах или сбоях |
| **Пайплайны под сценарии** | Настраиваемые режимы (прозрачный прокси, direct, scheduling, review…); смена сценария = смена политики |
| **Учёт и биллинг** | Отслеживание token/стоимости для личного контроля |

Коротко: **один вход для бэкендов и политик; агент пишет код.**

## Возможности

1. **Бэкенды / модели и пулы API-ключей**  
   Настройка в Web; для одного бэкенда — **несколько ключей с ротацией** при лимитах или отказах.

2. **Визуальный редактор пайплайнов**  
   Настройка поведения прокси на холсте (forward, schedule, review…); смена политики по сценарию без правки кода агента.

3. **`centag wrap` — неинвазивное подключение**  
   Запуск агента через wrap и направление трафика в Centag **без изменения настроек самого агента**.

4. **Прямая правка конфигов агента**  
   Указать API Base / Key агента на Centag как на обычный LLM-шлюз (мастер «Agent Setup» поможет записать конфиг).

Выберите удобный путь: wrap — меньше правок; конфиг — стандартный OpenAI-совместимый endpoint.
